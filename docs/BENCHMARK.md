# mdbeaver 자체 벤치마크 계획

> 목표: "mdbeaver 출력은 **더 적은 토큰**으로 **같거나 더 높은 AI 정확도**를 낸다"를 숫자로 증명한다.
> 이 문서도 살아있는 문서다. 지표·데이터는 결과를 보며 조정한다.

## 1. 무엇을 재나 (3가지 축)

| 축 | 질문 | 지표 | 정답 데이터 필요 |
|---|---|---|---|
| **A. 토큰** | 같은 문서를 몇 토큰으로 표현하나 | 토크나이저별 토큰 수 (문서별·합계, 한/중/영 분리) | 아니요 |
| **B. 보존도** | 원문 내용·구조를 얼마나 살렸나 | 텍스트 편집거리, 표 TEDS, 수식 CDM, 읽기 순서 (OmniDocBench 공식 지표) | 예 |
| **C. AI 정확도** | 그 마크다운만 보고 AI가 질문에 맞게 답하나 | 질의응답 정답률, **1천 토큰당 정답률**(효율) | 질문·정답 세트 |

핵심 숫자는 **C ÷ A (토큰당 정확도)**. 토큰만 줄이고 정확도가 떨어지면 의미 없다.

## 2. 데이터 세트 (30~60개로 시작)

| 유형 | 한국어 | 중국어 | 영어 | 확인 포인트 |
|---|---|---|---|---|
| 글 위주 (보고서·책 일부) | ✓ | ✓ | ✓ | 머리말 제거, 문단 |
| 논문 (표·수식) | ✓ | ✓ | ✓ | 표, LaTeX |
| 슬라이드 (PPTX) | ✓ | ✓ | ✓ | 제목, 표, 노트 |
| Word (DOCX) | ✓ | ✓ | ✓ | 제목 스타일, 병합 표 |
| 스캔본 PDF | ✓ | ✓ | ✓ | OCR (GPU 엔진 단계) |

- 출처: 라이선스가 명확한 것만 (arXiv CC-BY 논문, 공공누리 1유형 공공문서, 직접 만든 샘플). **원본은 저장소에 커밋하지 않고** 다운로드 스크립트 + 해시로 관리.
- 보존도(B)는 정답 마크다운이 있는 **OmniDocBench**를 그대로 사용 (라이선스 확인 후).

## 3. 비교 대상

- mdbeaver: 기본(AI 최적화), 페이지 번호 유지, 최적화 전 원본(raw)
- 기준선: PDF 순수 텍스트(pdftotext), MarkItDown, Docling, MinerU/PaddleOCR 원출력, HTML 출력
- (가능하면) 경쟁 서비스 결과를 수동으로 몇 개

## 4. 측정 방법

**A. 토큰**: tiktoken `o200k_base`(GPT 계열), Anthropic 토큰 카운트 API(Claude), Qwen 토크나이저(로컬) 3종. 한국어·중국어는 토큰 비용이 커서 언어별로 따로 보고.

**C. AI 정확도**
1. 문서마다 질문 10~20개: 사실 조회, **표 조회**, 수식·수치 계산, **페이지 인용**("몇 쪽?"), 요약형 일부
2. 질문은 강한 LLM이 **원본**을 보고 생성 → 사람이 검수 (오답 질문 제거)
3. 답변: 변환된 마크다운**만** 주고 고정 프롬프트, temperature 0
4. 채점: 정답이 짧으면 정확 일치, 아니면 LLM 채점 + 일부 사람 검수
5. 모델: **집 GPU의 로컬 모델(무료)**로 전체 실행, Claude/GPT로 일부 표본만 교차 확인 (비용 통제)

## 5. 실행 단계

| 단계 | 내용 | 필요한 것 |
|---|---|---|
| A | 토큰 벤치마크만 (LLM 불필요) | CPU, 지금 가능 |
| B | 질의응답 정확도 | 집 GPU + 로컬 LLM |
| C | OmniDocBench 보존도 | GPU 엔진 연결 후 |

결과는 `bench/results/<날짜>-<버전>.json`으로 버전 관리, 엔진·옵션 변경 때마다 재실행해 **회귀 확인**.

## 6. A단계 실행 방법 (구현 완료)

```bash
cd bench
npm install --registry=https://registry.npmmirror.com   # 처음 한 번
node make-samples.mjs          # 합성 샘플 생성 (동작 확인용)
npm run tokens -- samples      # 샘플로 실행
npm run tokens                 # 실제 문서: bench/docs/ 에 PDF·DOCX·PPTX 넣고 실행
```

- 웹사이트와 **똑같은 변환 코드**(`web/js`)를 Node에서 그대로 실행한다 (`node-shim.mjs`가 브라우저 환경을 흉내).
- 비교 변형: `plain`(구조 없는 복붙 텍스트), `raw`(정리 전), `mdbeaver`(기본 출력), `mdbeaver+pages`
- 다른 도구 비교: `bench/baselines/<도구명>/<원본파일명>.md`에 결과를 넣으면 자동으로 같이 집계
- 결과: `bench/results/<시각>-tokens.json` (커밋 대상), `bench/docs`·`bench/baselines`는 gitignore

### 첫 결과 (합성 샘플 3개, 2026-10-28) — 해석 주의

| 문서 | plain | mdbeaver | 비고 |
|---|---|---|---|
| PDF 12쪽 (머리말·쪽번호 있음) | 2364 | 2172 (−8%) | 머리말·쪽번호 제거 효과 |
| PPTX 4장 | 57 | 82 (+44%) | 제목 `##`, 글머리 `-` 등 **구조 표시 비용** |
| DOCX 한·중 | 373 | 402 (+8%) | 제목·표 구분자 비용 |

- 마크다운은 구조(제목·목록·표 칸)를 표시하는 만큼 **구조 없는 복붙 텍스트보다 토큰이 늘 수 있다.** 그 대가로 AI가 표·제목을 정확히 읽는지는 **C단계(정확도)**에서 확인해야 한다 → "토큰당 정확도"가 진짜 지표인 이유.
- 합성 샘플은 동작 확인용일 뿐이다. 실제 문서(특히 머리말·각주·장식이 많은 책·보고서)로 다시 재야 한다.

## 7. 주의할 점

- 토크나이저마다 결과가 다르다 → 한 숫자로 "몇 % 절감"이라 말하지 말고 범위로 보고
- 질문 생성 모델과 답변 모델이 같으면 유리하게 나올 수 있다 → 서로 다른 모델 사용
- 문서가 모델 학습 데이터에 있을 수 있다 → 최근 문서·직접 만든 문서 섞기
- 원본 문서는 재배포하지 않는다
